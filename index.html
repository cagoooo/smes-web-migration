兩個網站看起來一樣，是同步嗎？

判斷：不可以只看外觀。正式 AA 只認正式新站，準備站只作建置參考。

先做：把網址、頁面數、檢查日期一起記下來，再重新查正式 www。

本機對比度出現 1.00 或很多警示

判斷：這是找線索，不是單獨的 FreeGo 失敗證明；先看實際文字與背景是否真的看不見。

先做：保留現況，等正式 FreeGo 或人工審核明確指出問題再修。

FreeGo 顯示 NO，或 A／AA 數字看不懂

判斷：先確認輸入的是正式 www、型態是全網站、等級是 AA；不要拿舊測試站報告代替。

先做：保留報告與日期，查看是否為同一個共用問題，再修正後重測。

跳到 FreeGo 步驟 →

web 舊站顯示不安全或憑證失敗

判斷：web 是舊站 HTTPS 線，不納入 AA；DNS、CAA、nginx 與 TLS 要分開查。

先做：看 HTTP 是否 301、HTTPS 是否 200，再讀取憑證主體、SAN 與到期日。

完整操作路線12 個步驟

送審前8 個步驟

正式新站的 FreeGo 與人工審查結果，才是你校的判定依據；本機對比度工具只作線索。

  1. 先保留目前色彩設定，不因本機工具的一筆警示就全站換色
  2. 保留你校正式新站的 FreeGo 報告與人工審查紀錄
  3. 只有正式報告明確指出色彩問題時，才回到對應頁面精準修正

💡 不要把其他學校或測試站的結果當成你校的送審證據。

約 10 分

依你校內容盤點與官方要求，先整理需要放到新站的 PDF、ODT 或其他附件，並確認檔案可以選取文字。

  1. 把要搬入新站的檔案整理到校內安全保存的專案資料夾
  2. 後台 → 找到負責的處室 → 「檔案下載」頁面
  3. 上傳檔案並確認檔名有意義、沒有不必要的特殊符號
  4. 上傳完把每個檔案的網址記下來，後續頁面會用到

💡 檔名千萬不要改回英文或加括號——「檔名要有意義的中文、不可含 &#38; # % 等特殊符號」是規範明文。

約 25 分

共用區塊的問題可能在許多頁面重複出現；先處理版型、連結、替代文字與標題等共用問題，再逐頁補內容。

  1. 後台 → 「區塊管理」
  2. 找到要修正的共用區塊 → 點「編輯」
  3. 在編輯器切換到「原始碼」模式
  4. 貼上依你校盤點後整理的修正版內容 → 儲存
  5. 儲存後用瀏覽器檢查畫面、鍵盤操作與外部連結

🔒 公開版不提供任何單一學校的區塊草稿；請用你校自己的盤點結果建立修正版。

💡 修正後全站 title 只剩三種寫法：「PDF文件，另開新視窗」「ODT文件，另開新視窗」「另開新視窗」；正式站 Freego 自動檢測已完成，後續以人工檢測為準。

本機工具可能標出你校部分頁面或元件的色彩警示；這類結果先作線索，不直接當成送審失敗。

  1. 目前不強制修改這三個頁面的文字顏色，也不需要為了本機警示先停下來
  2. 若日後在後台啟用處室自訂顏色，仍要確認文字與背景對比度大於 4.5:1
  3. 只有正式 Freego 或人工審核報告明確指出問題時，才回到頁面編輯修正

約 30 分

依舊站與新站的內容盤點，補回審查需要且確實存在的必要頁面；不要為了湊數量自行創造內容。

  1. 下面點「複製」→ 內容會整份複製到剪貼簿（提示詞已經寫在裡面，不用另外設定）
  2. 開啟 Monica → 貼上 → 送出
  3. Monica 會回一段 HTML → 點它的複製按鈕
  4. 新站對應頁面 → 新增內容 → 編輯器左上「原始碼」→ 貼上
  5. 切回所見即所得 → 儲存

🔒 內容草稿可能含教師姓名、班級或聯絡方式；公開版不提供，請在校內安全位置準備自己的素材。

💡 頁面名稱、處室歸屬與內容數量，請以你校的資訊架構和主管機關要求為準。

約 25 分

依你校的處室與職務盤點補齊成員；公開教材只示範格式，不提供任何學校的姓名、Email 或電話。

  1. 使用校內安全保存的最新教職員名單，確認處室、職稱與聯絡資訊
  2. 到新站後台的「成員設定」分頁，依平台格式逐筆或批次輸入
  3. 再到「群組帳號設定」確認每位成員的登入與發文權限
  4. 完成後以測試帳號確認成員頁面與權限都符合你校需求

格式：職稱|姓名|Email|電話#分機|業務1;業務2

🔒 這一步需要你校自己的教職員資料；請勿把姓名、Email、電話或批次名單貼進公開 repository。

💡 「成員設定」只是讓業務職掌頁面有內容，不代表有發文權限——權限在「群組帳號設定」。

送審門檻之一是「讓行政人員進去發個兩三天的公告」，做出「這是一個活的網站」的樣子。

  1. 請各處室同仁登入新站，實際發幾則公告
  2. 連續 2～3 天都有新內容最好
  3. 公告內容注意：不要只放一張海報圖，海報上的文字要打進內文
  4. （沒有文字檔就把海報丟給 Monica，讓它把文字讀出來）

💡 研習原話：「只要海報裡面的內容有放在公告裡那就 OK；如果只寫『內容如題』然後丟兩張海報，那不行。」

約 5 分

本機腳本或瀏覽器檢查只用來找線索；正式判定以你校正式新站的 FreeGo 與官方人工審查為準。

  1. 想先找線索時，使用你校可控的檢查工具或瀏覽器開發者工具
  2. 檢查時一律輸入你校正式新站網址，不要把準備站當完成證據
  3. 把網址、日期、頁面範圍、報告與修正 commit 一起留下
  4. 先判斷問題是否為共用元件，再決定是否修正與重測

送審3 個步驟

正式新站、共構準備站與舊站各有不同任務；先確認你校的網址角色，再開始檢查或送審。

  1. 確認主管機關已將你校的正式新站網址指向新平台
  2. 確認內容編輯與 FreeGo 都只針對正式新站，不以準備站當完成證據
  3. 舊站若要保留，另行確認它的網址、轉址與 HTTPS，不要和 AA 工作混在一起
  4. 切換後依平台手冊重新產生處室設定與導覽列使用的網址資料
  5. 切換完成先測試首頁、選單、附件與重要頁面，再進行正式 FreeGo 檢測

💡 平台手冊明載：臨時網址切換成正式網址後，必須重新點擊「處室設定」標題，更新行政處室連結。參考網址：https://schoolweb.tyc.edu.tw/modules/tad_book3/page.php?tbdsn=4&tbsn=1

約 60 分

正式送審必要的軟體檢測；臨時網址的歷史結果不能取代正式 www，必須以正式網址的完整檢測為準。

  1. 在 FreeGo 輸入你校的正式新站網址，不要使用準備站或舊站
  2. 型態選「全網站」、等級選「AA」→ 開始
  3. 保留掃描日期、頁數、逾時頁面、違規代碼與設定，方便重測比較
  4. 若出現登入頁或特定路徑逾時，先記錄網址與時間，再依官方說明判斷，不要直接把所有逾時視為整站失敗
  5. 若有排除資料夾或其他檢測條件，記下設定與原因，申請時在備註說明
  6. 保留 FreeGo 的檢測檔作為校內紀錄；依數發部現行規定，申請時是否上傳以官方表單要求為準
  7. 查看 數發部 Freego 現行說明

💡 FreeGo 自動檢測、官方人工審查與 AA 標章核發是三個階段；請分開記錄，不要把其中一個寫成全部完成。

約 60 分

FreeGo 是申請前的自動檢測；接著依你校正式新站的實際頁面填寫自我評量，再等待官方分案與審查。

  1. 用 E 政府公務帳號登入無障礙網路空間服務網（需自然人憑證與機關代碼）
  2. 會員專區 → 網站專區 → 申請網站標章
  3. 依你校正式新站的實際狀況填寫自我評量，不要複製其他學校答案
  4. 送出後保存案件畫面與日期，依平台通知等待官方審核
送出前逐項核對：

💡 審核結果以平台通知為準；若退回或限期改善，依通知期限修正並回覆。流程說明請見數發部官方申請頁。

送審後1 個步驟

先完成核心內容與審查，再逐步加入相簿、公開資訊、外部連結與自製小站；每次新增仍要維持無障礙規範。

  1. 🥇 掛標章：依平台後台的無障礙標章區塊說明，填入官方核發資料
  2. 📷 相簿：依你校實際相簿逐一檢查分享連結、標題與替代文字
  3. 📊 會計室公開資訊：依規範與校務需求決定年度範圍，優先處理文字可選取的檔案
  4. 🔗 外部連結：逐條確認目的地、名稱、另開視窗提示與失效狀況
  5. 🛠️ 自製小站：先決定保留、搬遷或下線，再建立可維護的網址與責任人

💡 認證有效期 3 年，期間會不定期抽查，所以之後新增內容仍要維持同樣的撰寫紀律。
